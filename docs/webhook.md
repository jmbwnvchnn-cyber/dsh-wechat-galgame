# 微信桥接 webhook 契约

`POST /webhook/wechat` 需要 `Authorization: Bearer <bridgeToken>` 或 `X-Bridge-Token`，并发送 JSON：

```json
{"chat_id":"group-id","chat_type":"group","user_id":"sender-id","nickname":"昵称","text":"你好","msg_id":"unique-id","at_me":true,"is_self":false}
```

桥接器必须从已登录微信客户端的可靠消息元数据设置布尔值 `is_self`：自己发出的消息为 `true`，其他发送者为 `false`。不能确定来源时不要投递；缺少此字段或其值不是 `false` 的事件会被忽略。可额外配置 `botUserId` 作为第二道过滤。`at_me` 同样必须由桥接器根据实际提及信息设置。

微信数据库的引用文字可能归为通用卡片。桥接只接纳 `appmsg/type=57` 且带 `refermsg` 的引用文本，提取本次 `title`，仍独立验证真实 @ 和当前发送者；不把被引用正文、旧命令或引用作者当成新消息。其他文件/链接卡片与畸形 XML 保持忽略。引用文本也可进入受限的近期同群上下文。

正常处理返回 HTTP 200，`action: "reply"` 时桥接器发送 `reply`；`action: "ignored"` 时不发送。模型不可用或输出无效时也返回 `action: "reply"` 和对应的失败提示，此时先持久记录消息 ID，不改变好感或锁定胜者；重复投递（包括重启后）会被忽略。只使用契约中的 snake_case 字段，忽略其他别名。

模型 HTTP 429/5xx 采用参考项目的 700 ms 间隔，最多两次请求；401/402/403/404、错误 JSON 与内容校验失败不自动重复请求。每次请求保留 30 秒截止时间。仅重试模型生成，不重试微信发送。`/api/status` 的 `modelFailure` 仅包含固定错误码和时间，不包含提供商原始错误、聊天正文或密钥；成功模型请求会清除它。

真实 @ 后 `/好感`、`/记忆`、`/帮助` 为不调用模型、不计分的查询；`/记住 内容` 与 `/忘记 关键词` 或 `/忘记 全部` 操作发送者自己的长期事实。普通消息只提取受支持的明确第一人称自述，`/记住` 还支持部分第一人称事件；不能为他人设定记忆。档案按用户跨群保存，路线按群及用户区分，最近 20 条路线对话仍用于上下文。

随机事件默认启用（`randomEventsEnabled: true`），可在设置页保存开关。触发只计有效普通聊天：5 次后每次 20% 概率，第 12 次保底；每群冷却 30 分钟、每天最多 3 次（Asia/Shanghai）。新事件随普通模型回复生成，并衔接当前群话题、人设与玩家关系。期限固定 10 分钟；触发玩家直接取得个人选项，其他玩家用真实 @ 后 `/事件` 首次领取（额外一次模型请求，之后缓存）。每人的 A/B/C 单独排序并绑定本人；`/选择 A`、`选A` 或单独 A/B/C、1/2/3 选择，提交不调用模型。

每个事件每个用户一次。过期、重复、关闭、未领取或无效选择返回说明，不改变分数。选项通过现有好感结算事务写入分数、参与记录、消息去重与唯一胜者；好感范围 -100～100，正向分数计入每日上限，事件自身的单次参与限制代替普通聊天冷却和单字拦截。重启不续期、不刷新个人题；整局重置仅清除活动事件，保留群触发预算与冷却。旧事件格式兼容原有公共选项。

桥接的可选 `group_context` 是最多 8 条、10 分钟内的同群短文本（`chat_id`、`user_id`、`nickname`、`text`、`at`），只在真实 @ 验证后附加，并按 JSON 传输长度裁剪。服务端再次校验同群与字段类型，缺失时回落到本地同群历史；不把其他人的消息提升为当前玩家的长期事实，更正/遗忘后的旧资料会被过滤。

正向得分默认跨群按用户冷却 120 秒、每天（中国时区）最多 15 分，并在滚动 24 小时内抑制规范化重复或近似文本；规范化后不足两个字符不加正分。近似判断是启发式，可能误判或遗漏；负分不受这些正向限制。重置保留长期记忆和防刷记录。可用 `positiveCooldownSeconds`（0–86400）、`dailyPositiveCap`（0–1000）和 `repeatWindowHours`（0–168）配置。
