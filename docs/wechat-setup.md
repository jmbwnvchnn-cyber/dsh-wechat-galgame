# 微信桥接说明

桥接启动时确认唯一微信主窗口并固定句柄。运行中只要原窗口仍存在且聊天控件可验证，就继续使用原窗口；不会因为新增其他窗口就改绑或丢弃回复。原窗口关闭、登录界面、控件核验失败仍停止发送，不自动转向其他账号。启动日志记录绑定句柄，失败只记录固定安全原因。

## 设置步骤

双击 `start.bat`，在设置向导中检测已登录的微信账号，搜索并选择测试群，然后填写模型服务信息。群必须通过搜索结果选择，账号和群 ID 不需要手工录入。向导只会在本机读取选中账号的联系人数据库；搜索不会读取聊天正文或发送消息。

保存后桥接仍保持停止。点击“启动桥接”才会开始监听；运行时可能切换微信窗口并发送回复。请确认群成员知情同意、微信已登录，并且只有一个可见的微信主窗口。可随时回到设置页停止桥接。

## 安全与限制

- `config.json` 保存模型密钥、微信账号和群选择；`data/` 保存游戏、缓存与桥接状态。两者都只应留在本机，不要放进分享包或发给他人。
- “测试模型”仅在点击时请求模型服务，测试内容为短文本；检查返回的 JSON 格式，不会发送微信群消息。
- 桥接只接受数据库中可识别的真实 @；仅输入类似 `@昵称` 的文字不会触发。消息不可解析或无法确认当前群时会跳过。
- 程序不会补发离线消息。发送失败时请先人工检查群聊，避免重复操作。
- 此功能使用非官方个人微信接口，版本变化可能造成不兼容；仅用于 Windows 测试账号和获准的测试群。

## 常见问题

**没有检测到账号：** 登录微信后重试；确认当前用户有权读取微信数据目录。若仍失败，使用随附的 `diagnose-bridge.bat` 检查运行依赖。

**没有找到群：** 先输入群名中的一段关键词再搜索。结果过多时缩小关键词范围；重名时根据自己熟悉的群名逐个核对。

**启动失败：** 确认微信已登录、主窗口可见且只有一个，再检查账号是否能访问本地数据库。不要同时运行另一份桥接。

**UIA 未启用 / Qt 窗口兼容：** 部分微信版本只暴露 Qt 外壳，聊天控件树未启用。程序先只读检查唯一窗口下的聊天控件；缺失时会立即提示，不再一直等待。设置中的“允许微信无障碍兼容”默认关闭。明确勾选并保存后，授权会持续用于设置页启动、手动启动脚本及 `--check-connection`；仅在需要时才尝试修改当前微信进程的无障碍运行标志。不修改程序文件、不注入 DLL、不切换系统全局屏幕阅读器。登录界面、不明窗口或无法完整检查的控件树不会执行激活。候选验证失败由依赖库尝试恢复原标志，并停止连接；成功后仍须核验同一窗口的两个独立聊天控件。每次启动最多执行一次兼容激活，发送消息时不会重复激活。取消勾选并保存可禁止以后的激活；不会主动还原已经运行的微信进程，重启微信后重新检查。

**查看连接阶段：** 设置页会显示导入依赖、数据库、UIA、消息水位等阶段及用时；从设置页启动的总时限为 120 秒，超时会标明停留阶段并终止该桥接进程。独立的 `--check-connection` 也有 120 秒总时限；数据库或 COM 阻塞时，诊断进程以退出码 124 结束。`data/wechat-bridge/bridge.log` 记录固定阶段和安全错误说明，不记录密钥或聊天正文。

**只检查连接：** 在项目目录运行 `runtime\python\python.exe bridge\wechat_bridge.py --check-connection`，就绪后立即退出；不会轮询消息、请求模型、点击微信或发送消息，也不更新消息水位。默认不修改微信进程；只有配置中明确设置 `wechatBridge.enableAccessibility: true` 时才允许上述进程兼容激活。数据库检查仍可能生成本机解密缓存和日志。`diagnose-bridge.bat` 仍仅检查依赖及配置。

**需要更换模型密钥：** 在向导中输入新密钥并保存。留空会保留同一地址的已有密钥；更换地址后需填写新密钥，或勾选“明确清除已存密钥”。密钥不会在页面刷新后重新显示。

**已保存多个群，只搜索到其中一个：** 保存前会列出将被移除的已保存群。要保留其他群，请取消保存，继续搜索并勾选它们；确认列表后才会移除。

**更换微信账号：** 先停止桥接，再检测并选择新账号、搜索群并保存。桥接水位与数据库工作目录按账号隔离，切回旧账号时保留其水位；启动仍会跳过离线历史。
